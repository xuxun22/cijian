# 09 · 微信小程序支持计划

> 目标：让「此间」的打印工具同时支持 **网页** 与 **微信小程序**，家人在微信里就能把手机相册的照片、聊天里的文件发到家里打印机。
>
> - 日期：2026-10-22 · 状态：✅ **已确认并开工**——M-mp-1~3 已实现（待真机验证）；上线阻塞项：小程序备案 + 域名 ICP（见 §7/§8）

---

## 1. 关键技术判断（先说清"同时支持"的正确姿势）

**Astro 网页无法编译成小程序**——两者是完全不同的运行时（WXML/WXSS vs HTML/CSS）。
所以「同时支持」的正确架构不是改造 cijian-site，而是：

```
共享层：cijian-api（契约 v1.1 原样复用，后端零改动）
前端 ×2：
  ├── 网页（现状）：Astro on Vercel —— 所学/生活/工具箱，完整体验
  └── 小程序（新建）：原生微信小程序 —— 打印工具为主的家人入口
```

- 打印闭环的所有服务端能力（登录/上传/任务/状态/防重打）**已就绪，API 无需改动**。
- 小程序不上博客内容（所学/生活长文）：网页阅读体验更好，且博客类内容在小程序审核中有额外负担。小程序 v1 = **纯打印工具**。

## 2. 为什么小程序值得做（场景）

1. **相册直传**：`wx.chooseMedia` 原生调起相册/拍摄，手机照片 → 家里打印机，网页做不到的顺滑
2. **聊天文件导入**：`wx.chooseMessageFile` 可以直接从**微信聊天记录**里选文件（家人把 PDF 发到微信里 → 转发给小程序/文件传输助手 → 打印），这是网页端完全没有的能力
3. **家人触达**：小程序卡片可直接转发到家庭群，家人点开即用，无需记网址口令入口

## 3. 必须如实告知的平台限制

| 限制 | 说明 | 对策 |
|---|---|---|
| 小程序**无法访问手机文件系统**的任意文件 | 只能选：相册/拍摄（chooseMedia）、微信聊天中的文件（chooseMessageFile） | 手机"文件"App 里的 PDF → 先发到微信（文件传输助手）再选；或用网页端 |
| 服务器域名必须 **ICP 备案** 且在微信后台配置 | request + uploadFile 合法域名都要配 `https://api.whereami.cn` | 见 §7 待办 1：确认 whereami.cn 备案有效 |
| 发布需微信审核 | 每次版本更新都要提审（工具类目个人主体一般顺利） | 预留审核时间；首次提审附体验说明 |
| 隐私合规 | 相册/文件选择需在「小程序隐私协议」中声明，代码里要接隐私弹窗 API | 列入 M-mp-4 |

## 4. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | **原生小程序 + TypeScript**（不用 Taro/uni-app） | 单工具体量小；`wx.chooseMedia / wx.uploadFile(自带进度) / wx.chooseMessageFile` 原生 API 直用；无跨端框架演进风险。网页端是 Astro，Taro 也带不来代码共享 |
| 设计 | 纸墨朱砂设计令牌移植 WXSS（custom properties 小程序支持） | 与全站视觉同源 |
| 认证 | **复用单口令**：口令 → JWT → `wx.setStorageSync`；与网页同源同权 | 家人无感知差异；wx.login 身份体系列为 Phase 2 可选 |
| 打印能力 | 照片 `fit-to-page`、份数、黑白、双面 | 与网页工作台一致 |

## 9. 风险

| 风险 | 缓解 |
|---|---|
| api.whereami.cn 域名备案无效 → 域名配置被拒 | 先查备案状态；兜底：换用已备案的子域（如 `mp-api.whereami.cn` 同样指向该服务器） |
| 审核被拒（类目/隐私） | 工具类目 + 隐私协议齐全 + 提审附演示说明；被拒则按意见调整重提 |
| 非临时 auth key 累积设备（上轮已见） | 新 key 若未勾 Ephemeral，跑几次后在 Tailscale 管理台清理 runner 设备 |
